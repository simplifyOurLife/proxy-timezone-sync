# 权限与数据流

## 自动检测及应用

操作者是当前 Chrome 配置的扩展用户，前置条件为扩展已安装且启用。

1. 弹窗或 Chrome alarm 触发后台；关闭和手动指定路径优先，避免不必要外网查询。
2. 后台读取本地设置，可选扫描 localhost 代理端口；原生宿主机仅在用户启用且授予 nativeMessaging 后调用。
3. 向配置的 HTTPS 目标 trace 请求出口，省略凭据并拒绝重定向，校验域名字段和 IP；失败且未允许公共兜底时停止自动定位。
4. 把明确 IP 交给地理接口，拒绝空字段、IP 不匹配或不可用时区。全失败可使用已校验 trace 国家；多时区国家默认不猜测城市。
5. 按 includedDomains／excludedDomains 选择网页；不允许的域名不覆盖，并恢复已有接管。
6. 串行更新预注册脚本、同步状态、已有页面或 CDP；设置版本变化时旧结果作废。应用结果和诊断写入本地 storage。

外部副作用是向目标及地理服务发请求、在选定文档运行脚本、CDP 接管，以及写本地扩展状态。Windows 系统时区不变。

## 原生宿主机

安装器由用户单独执行，写当前用户 HKCU 注册项及本机启动清单；allowed_origins 绑定扩展 ID。扩展还需获授可选权限。宿主运行时只读代理相关进程、监听端口及系统代理，不联网。未安装／未授权时返回不可用，不阻止基础时区功能。

## 发布

维护者手动触发或推送版本标签后执行 GitHub 打包；PR 只做无密钥检查。签名密钥只从 Secrets 进入打包进程的临时文件，产物上传清单只包含 ZIP、CRX、校验和及文件清单。没有自动创建公开 Release。
