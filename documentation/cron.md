# Chrome 周期与后台调度

| 触发 | 默认／入口 | 行为 |
|---|---|---|
| tz-auto-refresh alarm | 每 5 分钟，用户可改 1–120 | background.js 读取最新设置并检测 |
| 扩展安装、浏览器启动、后台唤醒 | Chrome 生命周期事件 | 检查缓存及定时器，必要时刷新 |
| 浏览器代理变化 | proxy.settings.onChange | 请求重新检测 |
| 用户重新检测／修改设置 | 内部消息 | 手动刷新或重新应用 |
| 顶层导航／标签 URL 改变 | 导航事件 | 只负责 CDP 覆盖或范围恢复 |

Chrome 可能暂停或延后 alarm，不承诺严格墙上时间。并发检测合并，设置／代理变更保留一个待处理原因；应用串行执行，旧配置版本不能覆盖新配置。关闭及手动时区分支避开外网和端口扫描。

外部请求有超时，各地理接口按顺序降级，没有后台无限重试或维护者服务。弹窗显示最近状态和耗时；诊断详情和可选 debug 日志记录失败原因。证据：src/background.js、src/detect/geo.js。
