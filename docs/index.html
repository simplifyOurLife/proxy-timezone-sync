它怎么确定你的出口

整条链路只做一件事：把「这次探测请求的出口」变成「网页看到的时区」。每一步的结果都能在诊断里看到。

  1. 探测目标出口

    先请求目标站点的 trace 端点，取回它看到的那次请求的 IP。

    chatgpt.com/cdn-cgi/trace

  2. 按 IP 查地理

    用观测到的 IP 去查地理接口，并且要求接口返回同一个 IP，否则继续换下一个。

    ipwho.is/<IP>

  3. 确定目标时区

    优先取接口给的时区；只有国家时，对已核实的单一时区地区自动映射。多时区国家不猜城市。

    IANA tzdb

  4. 应用到网页

    在作用范围内的网页里写入时区，任务栏时钟与其他软件完全不受影响。

    Date / Intl

功能

出口即目标

代理按路径、IPv4／IPv6、进程或时间分别选节点时，其他请求的出口可能和这次探测不同。扩展确认的是该域名本次探测请求的出口，并把它写进诊断。

IP: 203.0.113.9
loc: SG        国家代码来自目标 trace
timezone: Asia/Singapore

单一时区地区自动映射

接口只返回国家时，这些地区可以确定时区，无需开启主要城市兜底。

  • 新加坡
  • 日本
  • 中国香港
  • 中国澳门
  • 中国台湾
  • 韩国
  • 泰国
  • 菲律宾

两种生效引擎

补丁模式在 document_start 注入时区适配器，页面无感知，不出现调试提示条。

CDP 模式用调试协议在内核层覆盖时区，覆盖更彻底，换来接管的标签页顶部提示条。

按域名收放

默认只改 chatgpt.com、openai.com 及其子域。加入「修改时区的域名」才会作用于其他站点，也可以排除指定域名。

不碰系统时区

Windows、macOS、Linux 的系统时区不被修改。任务栏时钟、其他软件、Chrome 内部页面和扩展设置页仍是系统时区。

诊断默认折叠

出口来源、每个地理接口的结果、本机端口与进程线索、异常原因都在弹窗的折叠区里，展开才有，不干扰日常使用。

诊断详情

自己验证，别信截图

在作用范围内的普通网页打开控制台，这四行就能说明问题。

  • 时区标识变成代理出口的城市时区
  • 偏移量跟着目标时区走
  • 时间戳没有被改动，仍接近 0
  • 显式指定 UTC 的格式化器不受影响

时区切换不承诺解决网站风控，也不能保证消除所有报错。它只负责让你看到的时区与出口地区一致。

控制台
Intl.DateTimeFormat().resolvedOptions().timeZone
// Asia/Singapore

new Date().getTimezoneOffset()
// -480

new Date(Date.now()).getTime() - Date.now()
// 接近 0

new Intl.DateTimeFormat('en-US', { timeZone: 'UTC' })
  .resolvedOptions().timeZone
// UTC

安装

  1. 拿到扩展

    从 Releases 下载 ZIP 解压，或者克隆仓库后直接加载目录。

    git clone https://github.com/simplifyOurLife/proxy-timezone-sync.git

  2. 加载到 Chrome

    打开 chrome://extensions/，开启右上角的开发者模式，选择「加载已解压的扩展程序」，指向仓库目录或解压后的目录。

    无需安装依赖，也没有构建步骤。

  3. 确认范围并检测

    点弹窗里的「立即重新检测」，查看目标时区、出口来源和异常提示。升级已有安装时，点扩展的「重新加载」，然后刷新目标网页。

作用范围默认只有 chatgpt.com 与 openai.com。要让其他站点也生效，把它们加进设置里的「修改时区的域名」；留空表示全部 HTTP(S) 网站。

常见问题

会修改系统时区吗

不会。任务栏时钟、其他软件、Chrome 内部页面和扩展设置页仍然是系统时区，只有作用范围内的网页会被改写。

切到新加坡后，钟面时间怎么没变

新加坡和上海目前同为 UTC+8，切换成功后钟面时间本来就相同。请用目标网页控制台里的 Intl.DateTimeFormat().resolvedOptions().timeZone 检查时区标识。

为什么默认只作用于 chatgpt.com

不同域名可能被代理规则分流到不同节点，出口并不通用。默认范围的意图是先把一个确定的目标做对，需要扩大时由你自己决定。

本地端口识别不准怎么办

端口探测只是辅助诊断，而且很容易被环境影响。TUN 模式、安全软件接管本地连接、自定义端口都会让它失准，此时应改为查看诊断里的出口来源，或安装可选的原生宿主机读取进程名。

补丁模式会被网站检测出来吗

可以。JS 适配器能被针对性识别，本项目不承诺「不可检测」。需要更彻底的覆盖时用 CDP 模式，代价是标签页顶部的调试提示条。

会上传我的数据吗

没有统计、账号上报、远程代码或远程配置。地理查询会把观测到的出口 IP 显式发送给第三方地理服务，请求不携带 Cookie 和登录凭据，结果只保存在本地。完整说明见仓库里的 PRIVACY.md。
