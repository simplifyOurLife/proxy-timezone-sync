# 浏览器时区修复计划

用户目标：让 Chrome 网页可见时区跟随目标网站的出口；不自动修改 Windows 系统时区，不承诺解决网站的全部检测或模型访问错误。

- [x] 用失败回归用例固定 Date 时间戳、夏令时、setter、格式化、恢复行为。
- [x] Date 内部始终保存真实毫秒，只转换本地 getter、setter、无时区构造和格式化；显式 Intl 时区保持调用方语义。
- [x] 使用持久化 document_start 注册脚本，将时区种子与补丁按顺序注入；已有页面同步更新，关闭时恢复原生引用。
- [x] 补丁与 CDP 互斥；统一作用域和域名排除；CDP 处理跨进程子目标并报告覆盖失败。
- [x] 先向 chatgpt.com 的 trace 端点查询该请求的出口，再按指定 IP 地理定位；无法确认时明确提示，不把通用接口出口当成目标站点出口。
- [x] 防止检测期间切换设置导致旧结果重新启用；完善状态、调试日志和失败提示。
- [x] 更新说明与自检页，运行自动测试及可用的浏览器验证；不执行 build，不提交或推送。

独立只读复核提出的启动关闭竞态、并发导航重新挂回旧 CDP、已有子会话例外更新、传统显式时区日期解析四项均已补回归并修复。1.1.2 修复仅返回新加坡等单一时区地区时无法自动切换；1.1.3 补充外部地理接口全失败时的 trace 国家/IP 降级，并把弹窗诊断内容默认折叠。最终 308 项自动检查及 34 项真实 Chromium 检查（含 3 项实网检查）通过，细节见《验证结果.md》。

修改前已留存完整本地备份；发布包不包含备份、测试日志和本机注册信息。工程交接见 documentation/architecture.md。
